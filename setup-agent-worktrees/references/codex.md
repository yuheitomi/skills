# Codex desktop

Official reference: https://learn.chatgpt.com/docs/environments/local-environment

Local environments configure setup scripts and actions for Codex desktop. The documented workflow uses the app settings pane and stores shareable configuration under `.codex`. Setup scripts run for new worktrees; this is not a general Codex CLI worktree hook.

Inspect `.codex/environments/` and preserve environment names, platform overrides, and actions. If a file says it is autogenerated, prefer the app settings workflow. Prepare the exact script to enter; use available supported UI tools when practical, otherwise deliver the script and specific UI step without claiming activation. Verify the installed app's format before directly generating a new TOML file.

The example repository has `.codex/environments/environment.toml`, `version = 1`, a name, and `[setup].script`. Its script uses `CODEX_SOURCE_TREE_PATH` and `CODEX_WORKTREE_PATH`. The official page does not document these variables or the TOML format (checked 2026-10); its example script (`npm install`) implies the script runs inside the new worktree. Treat the variables as observed, not guaranteed: prefer a helper that needs no variables, taking the destination from the cwd's `git rev-parse --show-toplevel` and the source from the main worktree (the first entry of `git worktree list --porcelain`), and accepting the variables only as validated overrides. Do not silently fall back to the current directory as the source.

When the app is not installed or its format cannot be confirmed, do not generate the TOML. Deliver the one-line setup command and the UI step (Codex → Settings → Local environments → setup script) instead, and report Codex integration as unverified.

Have the adapter resolve and validate the actual source and destination, then call the repository helper with quoted paths. Detect the destination through the documented worktree context; never hardcode a personal path. Install dependencies only when selected. Preserve the setup sequence required by repository lifecycle scripts.

If the user means Codex CLI, explain the desktop scope and offer a repository helper invoked by the user's existing worktree manager rather than inventing a CLI setup config. Report native integration separately from helper tests.
