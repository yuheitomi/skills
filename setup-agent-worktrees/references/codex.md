# Codex desktop

Docs: [local environments](https://learn.chatgpt.com/docs/environments/local-environment)

## Mechanisms

- **Local environments** (configured in the app: Settings → Local environments) define a setup script that runs for new worktrees, plus actions. Shareable config lives under `.codex/` (observed: `.codex/environments/environment.toml` with `version = 1`, a name, and `[setup].script`).
- This is a **desktop app** feature. Codex CLI has no equivalent worktree setup hook — for CLI users, a repo setup command invoked by their worktree manager is the realistic option.

## Observed behavior (verify against current docs)

- The TOML format and the variables `CODEX_SOURCE_TREE_PATH` / `CODEX_WORKTREE_PATH` were seen in a real repo but are not documented (checked 2026-10). The docs' example (`npm install`) implies the script runs inside the new worktree, so setup that derives paths from git (`git rev-parse --show-toplevel`, first entry of `git worktree list --porcelain`) doesn't depend on them.
- Files marked autogenerated are owned by the app; editing via the app's settings is safer than hand-editing.
- If the app isn't installed or its format can't be confirmed, generating TOML is guesswork; handing the user the script and the UI step is the honest alternative, with Codex integration reported as unverified.
